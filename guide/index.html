MAC APP STORE EDITION · VERSION 1.0

From installation
to your first insight.

Pipeline Atlas explores GitLab CI and GitHub Actions configuration on your Mac. It helps explain dependencies and configuration risks before you merge.

The App Store release is being tested. Check availability. Invited TestFlight testers can install the beta without buying the app.

1. Install and open

  1. Use an Apple silicon Mac running macOS 14 or later.
  2. Install Pipeline Atlas from its verified Mac App Store listing or a TestFlight invitation.
  3. Open the app. The full tool is available immediately, with no separate activation.
  4. Explore the built-in example to see a scheduled dependency regression.

2. Connect a repository

Choose a local Git repository folder through the app, or connect an authorized GitLab or GitHub account. Local analysis reads the selected folder on your Mac; it does not require Apple’s Command Line Tools. Enter provider credentials only in the app, using the minimum permissions you need.

3. Set the comparison and scenario

The current revision is the configuration you want to inspect. The baseline is the revision you compare against. A scenario describes the event and inputs that create a pipeline: push, merge request, schedule, tag, or manual run. Changed files and non-secret variables can affect inclusion.

For example, a build job limited to merge requests may disappear from a scheduled pipeline. If a scheduled deploy requires that build, Pipeline Atlas can report the missing dependency for supported rules.

4. Read the result

  • Explore: follow jobs, dependencies, and supported downstream pipelines.
  • Compare: distinguish new, existing, and resolved findings.
  • Scenarios: change event inputs to investigate conditional inclusion.
  • Findings: inspect errors, behavior changes, and incomplete analysis with available source information.

“Included” means eligible for the selected pipeline scenario. It does not mean the job ran or succeeded. Missing context and unsupported behavior remain unknown.

Company GitLab: VPN, proxy, and certificates

  1. Connect the IT-approved VPN.
  2. Ask IT for the GitLab API URL and permitted token scopes.
  3. Enter the explicit proxy and proxy credentials supplied by IT, if required.
  4. Import the company CA certificate and verify its fingerprint through your trusted IT channel.
  5. Test the connection, then select a repository your token can access.

This uses approved API access; it does not bypass Okta or gateway policy. Browser-only authentication and unsupported proxy configurations need IT guidance.

Parent and child pipelines

Supported static GitLab child and multi-project configuration and GitHub reusable workflows can be explored when accessible. Generated child configuration needs a supplied artifact. Access to another repository is never assumed.

Moving from the direct beta

In the direct beta, export a report as JSON. In the App Store edition, open Report History and choose “Import JSON report.” The imported report is stored in the App Store app’s local container. Keep your original file until you verify the import.
